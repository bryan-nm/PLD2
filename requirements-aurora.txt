# esm's own dependencies, MINUS the two groups that must never be pip-installed on Aurora.
# Installed separately because esm itself goes in with --no-deps; see scripts/aurora_env.sh, which
# is the thing to run. Keeping the list explicit beats guessing which imports the ESMFold2 path
# reaches: an under-installed dependency surfaces as an ImportError inside a fold rank.
#
# EXCLUDED, deliberately:
#   torch        -- esm 3.4.1 asks for >=2.11,<2.12 and the frameworks module provides 2.13 with
#                   XPU support compiled in. Letting pip satisfy that pin replaces a build tuned
#                   for this machine with a generic wheel, and folding stops seeing a GPU at all.
#   cuequivariance-torch, cuequivariance-ops-torch-cu13
#                -- CUDA-only, and their markers match linux/x86_64, so Aurora qualifies on paper.
#
# transformers is pinned below 5 because esm declares <5.0.0 and PyPI is already on 5.18. It does
# NOT supply the ESMFold2 model class -- no transformers release does, at any version -- so do not
# chase this pin when folding cannot find a model; that comes from esm.
transformers>=4.57.6,<5
